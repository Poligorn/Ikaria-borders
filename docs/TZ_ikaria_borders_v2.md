# ТЗ: мод «Ikaria Borders» (v2.1)

*Сервер MC-Ikaria · Minecraft 1.21.1 · NeoForge 21.1.x (на тестовом сервере 21.1.250) · дата: 19.11.2026*

Статус: v2, учтены ответы на вопросы v1. Кода пока нет. Репозиторий: https://github.com/Poligorn/Ikaria-borders. Работа идёт в ветках через PR, без мержа и публикации без явного OK.

**v2.1 (19.11.2026):** добавлен раздел 21 «Скриптуемое поведение зон (KubeJS)»: плагин KubeJS, события, динамические зоны, данные и флаги зон, управление картой, лимиты. Обновлены этапы, тест-план и открытые вопросы.

**Что изменилось с v1:**
- Мод называется «Ikaria Borders». Mod id `ikaria_borders`, пакет `com.poligorn.ikariaborders`, конфиг `config/ikaria_borders/`. Основная команда `/borders`, `/zones` оставлен как алиас.
- PvP включено везде, кроме спавна.
- На карте рисуем линии по чанкам. Точные линии по блокам не нужны.
- В диких землях разрешены **только серверные приваты**. Исключения для операторов и список UUID убраны. Операторы приватят там через `/opac server-claims`.
- Живой сервер работает на **чистом NeoForge**, не на гибриде (подтвердил пользователь). TAB 5.5.0 стоит как NeoForge-мод (раздел 17).

## 1. Зачем

Сейчас зоны сделаны скриптами KubeJS, и это работает плохо:

| Проблема | Причина |
|---|---|
| Сильные зависания сервера, приваты OPAC доходят до клиентов с задержкой 5–10 с | `world/zone_map_borders.js` рисует границы на картах Xaero через ~5800 фейковых серверных приватов OPAC. Все они идут через очередь синхронизации приватов OPAC, и настоящие приваты игроков ждут в ней. |
| Зоны в разных местах считаются по-разному | На карте зоны квадратные. `Ikaria.distFromSpawn`, HUD, `wild_claims_ban.js`, `claim_as.js`, `armed_mobs.js` и `distance_scaling.js` считают по кругу. В углах квадрата карта показывает не то, что действует на самом деле. |
| Правил по зонам (PvP, урон, мобы) нет | Скрипты этого не умеют, а писать такое на Rhino медленно и ненадёжно. |
| Форма зоны зашита в код | Квадрат и круг вокруг 0,0 задаются константами в `Ikaria.zones`. |

**Цель мода.** Один источник правды о зонах — конфиг на сервере. Из него:
1. рисуются границы на World Map и миникарте Xaero, **без единого привата OPAC**;
2. запрещаются приваты OPAC в диких землях;
3. действуют правила зоны: PvP, урон, спавн мобов;
4. зоны любой формы, приоритеты, наследование, перезагрузка без рестарта.

Индикатор зоны в HUD/TAB **остаётся в KubeJS** (`hud/hud_manager.js`). Мод только отдаёт ему текущую зону через API (раздел 9).

## 3. Объём MVP (одобрен)

1. Границы зон на World Map и миникарте Xaero (клиент; данные приходят с сервера; цвета, заливка/обводка, подписи, вкл/выкл).
2. Запрет приватов OPAC (и форслоада, и якорей) в диких землях; чистка уже существующих; исключения; сообщения.
3. Правила зоны: PvP, урон, спавн мобов (+ опции); приоритеты при пересечении.
4. Зоны любой формы в конфиге: круг, квадрат/прямоугольник, многоугольник, кольцо/разность; по измерениям; приоритеты; наследование; зона по умолчанию; горячая перезагрузка.

Плюс: команды, API для KubeJS (в т.ч. скрипты поведения зон — раздел 21), бюджет производительности, синхронизация, миграция, тесты.

**Не входит в MVP** — раздел 16.

## 4. Исследование: как рисовать на картах Xaero

Проверено по классам в jar с тестового сервера (`srv/mods`): `xaeroworldmap-neoforge-1.21.1-1.47.0.jar`, `xaerominimap-neoforge-1.21.1-26.6.0.jar`, `open-parties-and-claims-neoforge-1.21.1-0.32.7.jar`. Разбор через `javap`; исходников нет.

### 4.1. Как рисует OPAC (проверено)

- Подсветку приватов на картах делает **не сам OPAC, а Xaero**. Код лежит в jar карт:
  - World Map: `xaero.map.mods.pac.SupportOpenPartiesAndClaims.registerHighlighters(HighlighterRegistry)` создаёт `xaero.map.mods.pac.highlight.ClaimsHighlighter` (он наследует `xaero.map.highlight.ChunkHighlighter`).
  - Миникарта: аналог `xaero.common.mods.pac.SupportOpenPartiesAndClaims` → `xaero.common.mods.pac.highlight.ClaimsHighlighter` (наследует `xaero.common.minimap.highlight.ChunkHighlighter`).
- Подсветка **по чанкам**: `ChunkHighlighter.getColors(dim, chunkX, chunkZ)` возвращает массив из 5 цветов. Судя по байткоду `getChunkHighlitColor`, это центр и 4 стороны, а углы смешиваются. Так OPAC и рисует обводку: у крайних чанков привата цветные стороны. Порядок сторон — вывод из байткода, **не проверено** в игре.
- Кэш: World Map запекает подсветку в текстуры регионов (512×512 блоков). Перерисовка регулируется хэшем `calculateRegionHash(dim, regionX, regionZ)` и сбросом `MapDimension.onClearCachedHighlightHash(rx, rz)` / `MapWorld.clearAllCachedHighlightHashes()`. У миникарты: `xaero.common.minimap.highlight.DimensionHighlighterHandler.requestRefresh()`.

### 4.2. Можно ли стороннему моду зарегистрировать свою подсветку (проверено, без официального API)

- `HighlighterRegistry` (оба мода) — простой список. Метод `register(AbstractHighlighter)` публичный, но:
  - реестр создаётся заново **на каждую сессию** (вход в мир): World Map — в `xaero.map.WorldMapSession.init(...)`, миникарта — в конструкторе `xaero.hud.minimap.module.MinimapSession`;
  - сразу после регистрации встроенных подсветок (OPAC) вызывается `end()`, и список становится `Collections.unmodifiableList`. После этого `register()` падает.
  - Публичного события «зарегистрируй свои подсветки» нет. В World Map 1.47.0 метод `xaero.map.mods.SupportXaeroMinimap.registerMinimapHighlighters(Object)` пустой. Значит, подсветки World Map сами на миникарту **не попадают**, регистрировать нужно в оба реестра.
- **Вывод:** единственный рабочий путь — маленький клиентский mixin `@Inject(at = HEAD)` в `HighlighterRegistry.end()` для обоих классов (`xaero.map.highlight.HighlighterRegistry` и `xaero.common.minimap.highlight.HighlighterRegistry`). Перед «заморозкой» он добавляет наш `ZoneHighlighter`. Mixin подключается, только если соответствующий мод Xaero установлен (плагин mixin-конфига проверяет `ModList`).
- Риск: это внутренние классы Xaero, они могут поменяться в новой версии карт. Смягчение: mixin `require = 0`, версии Xaero фиксируются в сборке, при ошибке мод пишет в лог и работает без карты.
- Как делают другие: XaeroPlus (rfresh2/XaeroPlus на GitHub) тоже вешает mixins на внутренности Xaero (`MixinDimensionHighlighterHandler` и др.) и держит свой реестр «chunk highlight providers». Официального API для сторонних модов у Xaero нет. Это по веб-поиску, код XaeroPlus я не собирал. FTB Chunks рисует на своей карте, а не на Xaero, поэтому как образец не подходит.
- Лицензия Xaero: компилируемся против jar только как `compileOnly`, jar Xaero не распространяем. Условия лицензии Xaero я не перечитывал — **не проверено**.

### 4.3. Что это значит для вида границ

- Подсветка Xaero — **с точностью до чанка (16 блоков)**. Линия границы идёт по краю чанков, как сейчас у фейковых приватов. Тонкая линия точно по блокам потребовала бы mixin в рендер карты (`GuiMap` и рендер миникарты). Это хрупко, поэтому в MVP не делаем (раздел 16).
- Чтобы карта совпадала с правилами, «в зоне ли чанк» и для карты, и для запрета приватов считается **одинаково — по центру чанка** (как сейчас в скриптах). Для правил «в моменте» (PvP, урон, спавн) зона считается по точным координатам блока.
- Подсказка при наведении: `getChunkHighlightSubtleTooltip` / `BluntTooltip` — название зоны. Если чанк одновременно в привате OPAC, Xaero сам склеит подсказки через разделитель (`DimensionHighlighterHandler` уже это делает).

### 4.4. Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Фейковые приваты OPAC (как сейчас) | Зависания, очередь синхронизации, конфликты с приватами игроков. |
| Путевые точки Xaero (waypoints) | Только точки, линии и заливки нет; засоряют список точек игрока. |
| Свой оверлей поверх GUI карты без Xaero-API | Нужен mixin в рендер карты, хрупко. Оставлено на v2 для точных линий. |

## 5. Модель зон

### 5.1. Понятия

- **Зона** — `id`, измерение, форма, приоритет, родитель, правила, оформление на карте, метаданные.
- **Зона по умолчанию** измерения (`default: true`) покрывает всё измерение, у неё самый низкий приоритет. Например, «Дикие земли» для верхнего мира, «Ад», «Энд».
- **Текущая зона точки** — зона с наибольшим `priority`, содержащая точку. При равном приоритете побеждает объявленная выше в конфиге; при загрузке выводится предупреждение.
- **Наследование** (`parent`): правила зоны = правила родителя, поверх них свои. Цепочка заканчивается на `global` (общие умолчания в конфиге). Циклы — ошибка конфига.
- **Метаданные** (`meta`): произвольные пары ключ-значение (например `hud: "build"`, `dangerStep: 500`). Мод их не трактует, а отдаёт в API для KubeJS.
- **Только для карты** (`rules: false` или `mapOnly: true`): например линия «Край мира 10000», которая рисуется, но правил не меняет.

### 5.2. Формы

| Форма | Параметры | Примечание |
|---|---|---|
| `circle` | `center [x,z]`, `radius` | Внутри, если расстояние до центра < radius. |
| `square` | `center`, `half` | Квадрат 2·half, внутри, если max(|dx|,|dz|) < half. Нынешние зоны 100/1500/10000. |
| `rect` | `from [x1,z1]`, `to [x2,z2]` | Включительно по блокам. |
| `polygon` | `points [[x,z],…]` (≥3) | Проверка «луч» (even-odd). Самопересечения — предупреждение. |
| `union` | `shapes [...]` | Объединение. |
| `difference` | `base`, `minus [...]` | Кольцо = `square 1500` минус `square 100` и т.п. |

Все формы — в координатах блоков по X/Z, без учёта высоты (Y в MVP нет).

### 5.3. Корабли Sable / Create Aeronautics

Корабли Sable хранят блоки в отдельной «под-области» мира, поэтому координаты блоков корабля, а иногда и игроков на нём, могут быть далеко от реального места. Проверено в jar `sable-neoforge-1.21.1-2.0.6.jar`: есть `dev.ryanhcode.sable.Sable.HELPER` (`ActiveSableCompanion`) с методами `getContaining(Entity|Level,pos)` и `projectOutOfSubLevel(Level, Position)`.

Требование: если Sable установлен (мягкая зависимость), перед определением зоны позиция сущности или блока прогоняется через `projectOutOfSubLevel`, когда `getContaining(...)` не null. Это касается игроков, взрывов, урона и спавна. **Не проверено**: в каких случаях координаты игрока на корабле действительно «плотовые». Это отдельный пункт тест-плана.

## 6. Правила зоны

Значение правила: `true` / `false` / не задано (берётся у родителя). Если правило не задано нигде, действует ванилла.

### 6.1. PvP

| Правило | Что значит | Как |
|---|---|---|
| `pvp` | Урон игрок→игрок разрешён | `LivingIncomingDamageEvent` (NeoForge, есть в 21.1.250): если жертва — игрок, а источник урона (`getEntity()`, включая владельца снаряда, TNT, прирученного зверя) — другой игрок, и PvP запрещено → отмена. |
| `pvpCheck` | `victim` / `both` | `both` (по умолчанию): запрет, если **хотя бы один** из двух в зоне без PvP. Иначе из безопасной зоны можно стрелять в дикие земли. |
| `pvpPets` | Защищать прирученных питомцев игроков, как игроков | опция |

**Решение (v2):** PvP включено везде, кроме спавна. В конфиге `pvp: true` задан у зоны по умолчанию каждого измерения, `pvp: false` — только у `spawn`.

OPAC и OPAC Warfare свою защиту сохраняют. Действует самое строгое из правил мода и правил привата.

### 6.2. Урон

**Решение (v2):** для спавна решено только про PvP. Остальные правила урона, взрывов и спавна мобов есть в моде как опции, но **по умолчанию выключены** (ванилла) во всех зонах. Их можно включить в конфиге без пересборки.

| Правило | Пример | Как |
|---|---|---|
| `damage.deny` | `["minecraft:fall", "#minecraft:is_explosion", "#minecraft:is_fire"]` | Список ID типов урона и тегов `#…`. Отмена в `LivingIncomingDamageEvent`. |
| `damage.targets` | `players` / `all` | Кого защищаем: только игроков или всех живых. |
| `explosions.blockDamage` | `false` | `ExplosionEvent.Detonate`: убрать из списка разрушаемых блоки, стоящие в этой зоне. Взрыв на границе ломает блоки только снаружи. |
| `explosions.entityDamage` | `false` | Там же убрать сущности из `affectedEntities`. |
| `fireSpread` | `false` | **Опция, не MVP-обязательно**: в NeoForge нет события распространения огня, нужен mixin в `FireBlock`. Делаем, только если подтвердите. |

### 6.3. Мобы

| Правило | Пример | Как |
|---|---|---|
| `spawn.categories` | `{"monster": false, "creature": true, "ambient": true, "water_creature": true}` | `MobSpawnEvent.PositionCheck` → `FAIL` для запрещённых `MobCategory`. |
| `spawn.reasons` | `["NATURAL", "CHUNK_GENERATION", "PATROL", "REINFORCEMENT", "EVENT"]` | К каким `MobSpawnType` применяется запрет. Спавнеры, яйца и команды по умолчанию **не** трогаем. |
| `spawn.denyEntities` / `spawn.allowEntities` | `["hordium:*", "#minecraft:raiders"]` | Точечные исключения: ID, теги, маски модов. |
| `mobs.removeHostileOnEnter` | `false` | Опция: убирать враждебных мобов, зашедших в зону. Проверка раз в 2 с по загруженным чанкам зоны. По умолчанию выкл. |

Модовые мобы (Hordium, Hostile Skies, Dungeons Arise и т.п.) подпадают под запрет, если мод ставит им категорию `MONSTER`. Для остальных — `denyEntities`. Какие именно не помечены, **не проверено**.

### 6.4. Приваты

| Правило | Значение |
|---|---|
| `claims.allow` | `false` — запрет CLAIM (раздел 7). |
| `claims.forceload` | `false` — запрет FORCELOAD. |
| `claims.anchor` | `false` — запрет ANCHOR. |

### 6.5. Правила для Ikaria (v2)

| Зона | Форма | Приоритет | PvP | Урон / взрывы / мобы | Приваты |
|---|---|---|---|---|---|
| `spawn` «Спавн» | square half=100 | 30 | **нет** | ванилла (опции выключены) | можно |
| `build` «Зона застройки» | square half=1500 | 20 | да | ванилла | можно |
| `wild` «Дикие земли» (по умолчанию для верхнего мира) | всё измерение | 0 | да | ванилла | **только серверные** |
| `edge` «Край мира» | square half=10000, только на карте | 5 | — | — | — |
| `nether` (по умолчанию для Ада) | всё измерение | 0 | да | ванилла | можно, как сейчас (**открытый вопрос**) |
| `end` (по умолчанию для Энда) | всё измерение | 0 | да | ванилла | можно, как сейчас (**открытый вопрос**) |

Для Ада и Энда особых правил нет, пока не решено иначе: PvP включено, остальное — ванилла.

## 7. Запрет приватов OPAC

Повторяет логику `wild_claims_ban.js`, но надёжнее.

- Регистрирует один `xaero.pac.common.server.claims.action.listener.api.IClaimActionListenerAPI` через `OpenPACServerAPI.get(server).getServerClaimsManager().getActionListenerManager().register(...)` при `ServerStartedEvent`. Проверено в jar OPAC 0.32.7: методы `overrideClaimingActionPermission(UUID, ResourceLocation dim, int cx, int cz, ClaimingAction, IServerClaimsManagerAPI, ClaimActionPermissionOverride, MinecraftServer)` и `handleSuccessfulClaimingAction(...)`; `ClaimingAction` = CLAIM, UNCLAIM, FORCELOAD, UNFORCELOAD, UNCLAIM_UNANCHORED, ANCHOR, UNANCHOR.
- Слушатель снять нельзя, поэтому он один на весь запуск и читает **текущий** конфиг. После `/borders reload` ничего перерегистрировать не надо (в скрипте для этого были «поколения»).
- Проверка: зона центра чанка (cx·16+8, cz·16+8) → `claims.allow` / `forceload` / `anchor`. UNCLAIM / UNFORCELOAD / UNANCHOR разрешены всегда.
- Ответ: `ClaimActionPermissionOverride(FORBID, <сообщение>)`. Сообщение берётся из конфига, например «В диких землях приватить нельзя».
- Короткая надпись в actionbar: в MVP мод сам actionbar **не пишет**, потому что по правилам проекта в него пишет только `hud_manager`. Мод шлёт событие `ZoneClaimDeniedEvent`, а KubeJS вызывает `Ikaria.hud.flash`. Сообщение от OPAC в чат приходит и так.
- **Исключения:** только серверные приваты (`SpecialClaimOwners.SERVER`). Решение v2: исключений для операторов и списка UUID **нет**. Оператор, которому нужен приват в диких землях, ставит серверный приват через `/opac server-claims`. Приваты операторов как игроков в диких землях запрещаются и снимаются чисткой так же, как у всех.
- Прямой `claim()` из API OPAC (как в `claim_as.js`) слушатель обходит: так устроен OPAC. Чистка такие приваты всё равно найдёт.
- **Чистка** существующих: проход по `getPlayerInfoStream()` → `getStream()` по измерениям → позиции; снимаются приваты (и форслоад) в чанках с `claims.allow=false`, кроме исключений.
  - Когда: через 30 с после старта, после `/borders reload` (если менялись зоны приватов) и вручную. Периодическая — опция, по умолчанию раз в 60 мин. Раз в 5 мин, как в скрипте, не нужно: новые приваты и так блокируются.
  - Порциями до N чанков за тик (по умолчанию 200), на основном потоке, потому что API OPAC не потокобезопасен.
  - Владелец онлайн получает сообщение (через событие → KubeJS, либо системным сообщением, если KubeJS не подписан). В лог: `[ikaria_borders/claims] снято N у <ник> (<uuid>)`.
  - Режим `dryRun` в конфиге: только отчёт.
- **OPAC Warfare / aeroclaims / opacbonusclaims**: всё, что приватит через `tryToClaim*`, пройдёт через наш слушатель. Как OPAC Warfare захватывает территорию и не сломает ли запрет войны в диких землях, **не проверено**.
- **Очистка наследия скрипта**: `/borders legacy-cleanup` снимает серверные приваты в подконфигурациях `ikaria-spawn`, `ikaria-500`, `ikaria-wild`, `ikaria-edge` (по `getFullName` / sub-index), порциями, с отчётом. Нужна, если `/ikariamap clear` уже не выполнить. Сами подконфигурации удаляются через OPAC, если API это позволяет. **Не проверено**.

### 8.3. Загрузка и проверка

- `/borders reload` читает файл, полностью проверяет его (типы, `id` уникальны, `parent` существует, нет циклов, многоугольник ≥3 точек, измерение существует) и только потом подменяет конфиг одной атомарной заменой ссылки. **При ошибке остаётся старый конфиг**, ошибки с путём к полю (`zones[2].shape.half`) уходят в ответ команды и в лог.
- При старте с битым конфигом сервер не падает: мод работает с пустыми зонами и громко пишет в лог. Альтернатива — падать. **Вопрос** (раздел 19).
- После успешной перезагрузки: рассылка клиентам (раздел 10), событие `ZonesReloadedEvent`, при необходимости чистка приватов.

## 9. API для KubeJS и других модов

Пакет условно `com.poligorn.ikariaborders.api` (имя уточним). Класс `IkariaBordersAPI`, статические методы; из KubeJS — через `Java.loadClass`. Будут ли пакеты мода пропущены фильтром классов KubeJS, **не проверено** (мы уже видели, что `java.nio.file.Files` он блокирует) — проверить первым делом.

| Метод | Возвращает |
|---|---|
| `zoneAt(Level, double x, double z)` | `ZoneView` (никогда не null — есть зона по умолчанию; если её нет — пустая зона `none`) |
| `zoneAt(ResourceKey<Level>/String dim, x, z)` | то же |
| `zoneOf(Entity)` | с учётом корабля Sable; для игроков — из кэша (обновляется раз в 10 тиков) |
| `zoneOfChunk(dim, cx, cz)` | по центру чанка, как для приватов и карты |
| `isClaimAllowed(dim, cx, cz, UUID owner)` | с учётом исключений |
| `zones(dim)` / `zone(id)` | список и поиск |
| `ZoneView` | `id()`, `name()`, `priority()`, `color()`, `meta(String key)`, `rule(String path)`, `parentId()` |

События (шина `NeoForge.EVENT_BUS`; в KubeJS — `NativeEvents.onEvent(<класс>, handler)`, этот приём уже работает в `waystones/waystone_privates.js`):

| Событие | Когда |
|---|---|
| `PlayerZoneChangeEvent(player, from, to)` | игрок сменил зону, в т.ч. при входе, смене измерения и телепорте; проверка раз в 10 тиков |
| `ZoneClaimDeniedEvent(player/uuid, dim, cx, cz, action, zone)` | отказ в привате |
| `ZoneClaimsSweptEvent(owner, count)` | чистка сняла приваты |
| `ZonesReloadedEvent` | конфиг перезагружен |

Как это поможет HUD: `hud_manager.js` вместо своего `zoneOf()` по кругу берёт `IkariaBordersAPI.zoneOf(p).meta('hud')` и на `PlayerZoneChangeEvent` сразу отправляет префикс в TAB. Проблему «застревающего» префикса это само не решает (она, судя по всему, в доставке в TAB), но убирает расхождение круг/квадрат и даёт точный момент смены зоны.

## 10. Сеть и синхронизация

- Клиент без мода может войти, всё серверное работает, просто нет линий на карте. Сервер без мода — клиентская часть молчит.

## 11. Клиент: отрисовка

- `ZoneHighlighter` (свой класс для World Map и для миникарты) регистрируется mixin-ом перед `HighlighterRegistry.end()` (раздел 4.2).
- Для каждого чанка: зона по центру чанка (те же формулы, что на сервере) → цвет заливки (если `fill`) и цвета сторон для сторон, где соседний чанк в другой зоне с `map.show` и выбранной `side`.
- Кэш: результаты по региону 32×32 чанка (1024 проверки) считаются один раз на версию конфига и хранятся в LRU (например 256 регионов). `regionHasHighlights` быстро отсекает регионы по габаритам (AABB) зон: регион без границы и без заливки → false без расчёта.
- `calculateRegionHash` = хэш версии конфига + клиентских настроек. При новой версии — `clearAllCachedHighlightHashes()` / `requestRefresh()`, и Xaero перерисует.
- Подсказка при наведении — `label` / `name`.
- Клиентские настройки (`ikaria_borders-client.toml`): `enabled`, `worldMap`, `minimap`, `opacityMultiplier`, `hiddenZones` (список id), кнопка-переключатель (keybind, по умолчанию не назначена).
- Миникарта в Аду отключается скриптом `nether_rules.js` (код Xaero). Мод это уважает и ничего не обходит.

## 12. Производительность (бюджет)

| Где | Бюджет | Как |
|---|---|---|
| Поиск зоны точки | ≤ 1 мкс при ≤ 50 зонах | Зоны измерения отсортированы по приоритету; сначала проверка AABB, потом форма; первая подходящая — ответ. Многоугольники — с предрасчётом AABB. |
| Частые события (спавн, урон) | без аллокаций в горячем пути | Кэш «чанк → зона» по центру чанка на измерение (`Long2ObjectOpenHashMap`, сброс при reload) — для спавна и приватов. Для урона — точный расчёт. Если ни у одной зоны нет правил спавна/урона, обработчик выходит сразу. |
| Отслеживание игроков | раз в 10 тиков, O(игроки × 1) | Сравнение по кэшу чанка; полный пересчёт только при смене чанка. Никаких тяжёлых per-tick операций. |
| Чистка приватов | ≤ 200 чанков за тик, ≤ 2 мс/тик | Порциями, по расписанию, не каждые 5 минут. |
| Слушатель OPAC | O(1) | кэш чанка + сравнение владельца с `SpecialClaimOwners.SERVER`; без обращений к `ProfileCache`. |
| Сеть | ~1 пакет на вход/reload | Никаких приватов OPAC → очередь синхронизации OPAC больше не забивается. |
| Клиент | расчёт региона ≤ 1 мс, только при первом показе | LRU-кэш. |

Приёмка: на тестовом сервере `spark profiler` 5 минут с ботами/игроками — мод не выше 0,5 % тика; `/opac claims claim` доходит до карты так же быстро, как без мода.

## 21. Скриптуемое поведение зон (KubeJS)

Цель: поведение зоны пишется скриптами KubeJS без пересборки мода. Примеры идей: «живые» дикие земли, аномалии, ветер и экология. Мод отвечает за геометрию, события, хранение, синхронизацию с картой и лимиты. Что происходит в зоне, решает скрипт.

Только сервер: `server_scripts`. Клиентских скриптов нет, клиент получает лишь данные для карты (раздел 10). Скрипты Ikaria продолжают следовать правилам проекта: папка по смыслу, русский заголовок с настройками наверху, общий объект `Ikaria`, сообщения игрокам — только через `Ikaria.hud`.

### 21.1. Плагин KubeJS

- Плагин мода: класс, реализующий `dev.latvian.mods.kubejs.plugin.KubeJSPlugin`, объявлен в `kubejs.plugins.txt` в корне jar. Так делают и другие моды, например LootJS. Проверено в jar KubeJS 2101.7.2 и LootJS 3.7.0.
- Используем `registerBindings(BindingRegistry)` и `registerEvents(EventGroupRegistry)`. KubeJS — **мягкая** зависимость: без него плагин не загружается, мод работает как обычно.
- Глобальный объект **`IkariaBorders`** — запросы, динамические зоны, данные, флаги, карта. Он не требует `Java.loadClass` и обходит вопрос фильтра классов из раздела 9.
- Группа событий **`IkariaBordersEvents`**. У событий зон есть «цель» — id зоны: `IkariaBordersEvents.playerEnter('wild', e => …)`. Без цели обработчик получает события всех зон.
- Java API из раздела 9 остаётся для других модов. Плагин — тонкая обёртка над ним.

### 21.2. События

Порядок: сначала встроенные правила зоны (раздел 6), потом скрипты. **Скрипт может только ужесточить**: отменить то, что правило разрешило. Разрешить запрещённое правилом он не может. Чтобы ослабить правило, нужно изменить сам конфиг или сделать runtime-переопределение (21.5), чтобы это было видно в `/borders info`.

| Событие | Когда | Отменяемое | Что есть в `e` |
|---|---|---|---|
| `ready` | после старта сервера, `/reload` и `/borders reload` | — | `server`. Здесь скрипты создают свои динамические зоны и регистрируют флаги. |
| `playerEnter` / `playerLeave` | игрок вошёл в зону / вышел из неё, в т.ч. при смене измерения и телепорте | нет | `player`, `zone`, `from`, `to` |
| `playerTick` | пока игрок в зоне, раз в N тиков (по умолчанию 20; свой интервал у зоны: `scripting.playerTickInterval`, минимум 5) | нет | `player`, `zone`, `depth` |
| `zoneTick` | раз в N тиков для зоны (по умолчанию 100, минимум 20), если в ней есть игроки или загруженные чанки | нет | `zone`, `level`, `players` (кэш), `forEachLoadedChunk(fn, limit)` с лимитом |
| `chunkLoad` | чанк зоны загрузился (полностью, на основном потоке, после генерации) | нет | `level`, `chunkPos`, `zone`, `isNew` (сгенерирован впервые) |
| `mobSpawn` | естественный и прочий спавн моба в зоне (`FinalizeSpawnEvent`) | да | `entity`, `spawnType`, `zone`, `depth`, `replace(entityId)` — отменить и поставить другого моба (спавн на следующем тике, учитывается лимит) |
| `blockBreak` / `blockPlace` | игрок ломает или ставит блок в зоне | да | `player`, `block`, `pos`, `zone` |
| `damage` | живая сущность получает урон в зоне (`LivingIncomingDamageEvent`) | да; можно менять `amount` | `entity`, `source`, `attacker`, `amount`, `zone` |
| `claimAttempt` | попытка привата, форслоада или якоря OPAC в зоне | да, можно только запретить, с сообщением `e.deny('…')` | `ownerUuid`, `player` (если онлайн), `action`, `chunkPos`, `zone` |
| `dynamicZoneExpired` | у динамической зоны истёк срок | нет | `zone` |

Все позиции уже пересчитаны с учётом кораблей Sable (раздел 5.3).

```js
// Пример: в диких землях глубже 2000 блоков ночью вместо зомби — усиленные мобы
IkariaBordersEvents.mobSpawn('wild', e => {
  if (e.depth > 2000 && !e.level.isDay() && e.entity.type == 'minecraft:zombie') e.replace('minecraft:husk')
})
```

### 21.3. Запросы

| Метод | Что даёт |
|---|---|
| `IkariaBorders.zoneAt(level, x, z)` / `zoneOf(entity)` | текущая зона (с наибольшим приоритетом) |
| `IkariaBorders.zonesAt(level, x, z)` | все зоны в точке по убыванию приоритета |
| `IkariaBorders.zone(id)` / `zones(dim)` | зона по id / список |
| `IkariaBorders.playersIn(id)` | игроки в зоне (кэш, без перебора) |
| `IkariaBorders.isInside(id, level, x, z)` | точка в форме зоны (без учёта приоритетов) |
| `IkariaBorders.distanceToBorder(id, x, z)` | расстояние до границы формы в блоках: + внутри, − снаружи |
| `IkariaBorders.depth(entity)` / `depth(id, x, z)` | «глубина» в зоне — насколько точка ушла внутрь от края. Для зоны по умолчанию (например `wild`) это расстояние до ближайшей границы зон с бо́льшим приоритетом. Готовая основа для тиров опасности: `floor(depth / 500)`. |

Для квадрата, круга и прямоугольника расстояния считаются формулой, для многоугольника — по ближайшему ребру (до 64 точек).

### 21.4. Динамические зоны (во время игры)

Скрипт может создавать, двигать и удалять зоны на лету: аномалии, временные события, «дышащая» граница.

```js
// Аномалия на 10 минут, с подписью на карте
var a = IkariaBorders.dynamic.create({
  id: 'anomaly_' + n, dimension: 'minecraft:overworld', parent: 'wild', priority: 40,
  shape: { type: 'circle', center: [x, z], radius: 48 },
  rules: { custom: { 'ikaria:anomaly': 1 } },
  map: { show: true, color: '#7F00FF', style: 'fill+outline', label: 'Аномалия' },
  ttlSeconds: 600, persist: false
})
```

- Id получают префикс `dyn:` (`dyn:anomaly_3`) и не пересекаются с id из конфига.
- У объекта зоны есть `move(x, z)`, `resize(…)`, `setShape(…)`, `setPriority(…)`, `remove()`, а также методы карты и правил (21.5, 21.6).
- `persist: true` — зона сохраняется в мире (SavedData `ikaria_borders_dynamic`) и переживает рестарт. `persist: false` — живёт до рестарта или `/reload`; после `/reload` скрипт пересоздаёт её в `ready`.
- `ttlSeconds` считается по игровому времени сервера. По истечении — `dynamicZoneExpired` и удаление.
- **Изменение зон из конфига** на лету: `IkariaBorders.zone('build').overrideShape(…)` — так можно сделать «живую» границу диких земель. Переопределение не сохраняется: при рестарте и `/borders reload` форма возвращается к конфигу. Переопределение с `persist` — открытый вопрос.
- **Приваты не зависят от динамики.** Запрет приватов и чистка (раздел 7) всегда считаются по **статической форме из конфига**. Двигающаяся граница и аномалии не могут снять ни одного привата. Чтобы аномалия запрещала новые приваты, есть только `claimAttempt` (запрет новых, без чистки).
- **Лимиты** (настраиваются в `global.scripting`):

| Лимит | По умолчанию |
|---|---|
| динамических зон одновременно | 64 |
| точек в многоугольнике | 64 |
| изменений формы одной зоны | не чаще 1 раза в секунду (лишние объединяются, применяется последнее) |
| отправка изменений на карту | не чаще 1 раза в 5 с на зону, пакетом для всех зон; пакет уходит, только если изменился хотя бы один чанк (карта всё равно по чанкам) |
| `mobSpawn.replace` | не больше 20 подмен за тик на сервер |

При превышении лимита вызов не падает: возвращает `false` и пишет в лог (не чаще раза в минуту).

### 21.5. Данные зоны, свои флаги, переопределение правил

- **Постоянные данные зоны:** `zone.data` — ключ-значение (строки, числа, логические значения, небольшие вложенные объекты). Хранится в SavedData мира, до 16 КБ на зону. Пример: «уровень заражения», время последней аномалии. Для временного состояния (до рестарта) — `zone.temp`.
- **Свои флаги правил:** скрипт объявляет `IkariaBorders.registerFlag('ikaria:danger_mult', 1.0)`, значение задаётся в конфиге (`rules.custom`) или в динамической зоне и наследуется по `parent`, как обычные правила. Читается через `zone.flag('ikaria:danger_mult')`. Сам мод такие флаги не трактует. Незнакомый флаг в конфиге — предупреждение, не ошибка.
- **Переопределение правил во время игры:** `zone.setRule('pvp', false, { ttlSeconds: 300 })`, `zone.clearRule('pvp')`. Не сохраняется (кроме случая из открытых вопросов). Видно в `/borders info <id>`, сбрасывается `/borders overrides clear [id]`. Ограничение «только серверные приваты в диких землях» переопределить нельзя: правило `claims` закрыто для runtime-изменений.

### 21.6. Карта во время игры

- `zone.setColor('#FF0000')`, `setLabel('…')`, `setVisible(true|false)`, `setStyle('outline'|'fill'|'fill+outline')`, `setOpacity(0.4)`.
- Изменения уходят клиентам с тем же лимитом, что и формы (21.4). Клиент сбрасывает кэш только регионов, которые задела зона (её AABB до и после).
- Пульсацию цвета каждые полсекунды сделать нельзя, и так задумано: перерисовка регионов Xaero дорогая. Минимальный шаг — 5 с.
- Видимость зоны только для отдельных игроков (например, аномалию видят лишь те, у кого есть прибор) — открытый вопрос, в базовой версии нет.

### 21.7. Производительность и безопасность

- **Всё на основном потоке сервера.** Вызов API из другого потока — ошибка с понятным текстом.
- **Изоляция ошибок.** Каждый обработчик обёрнут: ошибка скрипта не ломает мод, событие или тик. В лог пишется `[ikaria_borders/script] <событие> <зона>: <ошибка>`, одна и та же ошибка — не чаще раза в минуту. Если у обработчика больше 50 ошибок за минуту, он отключается до `/reload` с предупреждением в лог и операторам онлайн.
- **Бюджет времени.** Мод меряет время обработчиков. Если `zoneTick` и `playerTick` вместе дольше 2 мс/тик в среднем за 10 с — предупреждение. Если дольше 10 мс — следующие вызовы этой зоны пропускаются до конца секунды. Статистика: `/borders scripts` (время по событиям и зонам, ошибки, отключённые обработчики).
- **Троттлинг по устройству событий:** `playerTick` не чаще раза в 5 тиков, `zoneTick` не чаще раза в 20 тиков. `forEachLoadedChunk` обрабатывает не больше заданного лимита за вызов (по умолчанию 64) и продолжает с того же места в следующий раз. Тяжёлые события (`mobSpawn`, `damage`) вызывают скрипт, только если для этой зоны есть хоть один обработчик. Иначе ноль накладных расходов.
- **Перезагрузка.** `/reload` (KubeJS) сам снимает старые обработчики. Мод удаляет непостоянные динамические зоны и runtime-переопределения, потом вызывает `ready`. `/borders reload` перечитывает конфиг, сохраняя динамические зоны, и тоже вызывает `ready`.
- **Особенности Rhino** (по опыту проекта): `var` в циклах и try-блоках, не ловить Java-исключения там, где Rhino их не ловит. Это будет в README плагина.

### 21.8. Примеры сценариев

**1. «Живые» дикие земли.** Ночью граница диких земель «наступает» на 64 блока внутрь зоны застройки, днём возвращается. Чем глубже игрок в диких землях, тем выше опасность.
- `ready`: запомнить исходный размер `build` (1500).
- `zoneTick('build')` раз в 30 с: если ночь — `overrideShape` квадрат 1436, днём — 1500. Шаг кратен 16, чтобы на карте граница прыгала ровно на чанки.
- `playerTick('wild')`: `tier = floor(depth / 500)` → строка опасности через `Ikaria.hud.show(...)`. Это замена нынешнего `distance_scaling.js` с кругом.
- `mobSpawn('wild')`: чем больше `tier`, тем чаще подмена на усиленного моба (как `armed_mobs.js`).
- Приваты на «наступившей» полосе не трогаются (21.4).

**2. Аномалия** (по лору — отголосок «аномалии пустоты» из дневников).
- Раз в 20–40 минут в диких землях рядом со случайным игроком (не ближе 300 блоков) скрипт создаёт `dyn:anomaly_N`: круг 48 блоков, `ttlSeconds: 600`, фиолетовая заливка на карте с подписью «Аномалия».
- `playerEnter`: предупреждение через `Ikaria.hud.flash`. `playerTick`: слабость/тошнота, частицы. `mobSpawn`: свои мобы. `blockBreak`: из определённых блоков — редкий лут (награда за риск).
- `zone.data.charge` растёт, пока внутри есть игроки. На максимуме аномалия «схлопывается» раньше срока (`remove()`) и выдаёт награду.
- `dynamicZoneExpired`: убрать эффекты, сообщить игрокам рядом.

**3. Ветер и экология.**
- В конфиге или скриптом у зон задаётся свой флаг `ikaria:wind` (направление и сила) и `ikaria:ecology` (например «разрастание лозы»).
- Ветер для кораблей: в Sable 2.0.6 есть `dev.ryanhcode.sable.api.SubLevelHelper.registerWindProvider(BiFunction<Vector3dc, Level, Vector3dc>)` (сигнатура проверена в jar). Мод может зарегистрировать **один** такой провайдер, который отдаёт сумму ветров зон в точке по флагу `ikaria:wind`, с кэшем по чанку. Как Sable применяет этот ветер к кораблям и как это сочетается с AeroWeather — **не проверено**. У AeroWeather публичного API я не нашёл (только команды и конфиг). Поэтому сценарий — опция, а не обязательство.
- Экология: `zoneTick` + `forEachLoadedChunk(fn, 16)` — в случайных блоках загруженных чанков дикой зоны медленно разрастаются растения или «порча», в зоне застройки — нет. Строго в рамках лимита чанков за вызов.

### 21.9. Что проверено

- Механизм плагинов KubeJS 7 (`KubeJSPlugin.registerBindings/registerEvents`, файл `kubejs.plugins.txt`) — по jar KubeJS 2101.7.2 и LootJS 3.7.0.
- `SubLevelHelper.registerWindProvider` в Sable 2.0.6 — по jar.
- **Не проверено:** синтаксис событий с «целью» (`playerEnter('wild', …)`) для своих групп в KubeJS 7 — так устроены события KubeJS, но на своей группе я это не собирал; влияние ветра Sable на корабли; отсутствие API у AeroWeather.
